# 多源岗位发现与核验分级设计

## 目标

把岗位库从“少量官网首页扫描”扩展为公开可访问的多源发现系统：企业官方招聘系统、招聘软件公开岗位页、高校就业网、地方国资招聘平台和公众号公开文章都可以提供线索。网站保留符合 2027 届本科建筑/相关背景规则的岗位，并清楚区分官方已核验和待核验信息。

## 来源优先级

1. 企业官方招聘系统、企业官网职位页：作为官方投递记录。
2. 央国企及地方国资公开招聘平台：用于发现岗位与官方链接。
3. 高校就业信息网：用于发现校招公告与官方投递链接。
4. 招聘软件的公开网页：作为线索来源；不使用登录、验证码、个人账号或 App 私有接口。
5. 可公开访问的公众号文章、新闻稿和招聘公告页：作为线索来源；不抓取微信小程序或登录后内容。

首轮审计对象包括智联招聘公开页、前程无忧公开页、猎聘公开页、BOSS 直聘公开网页、高校就业网、国聘/地方国资公开平台，以及建筑央企/设计院官网招聘页。只有技术审计确认可公开、可稳定访问的来源才接入每日自动任务。

## 数据模型与展示

每个岗位增加以下内部字段：

- `source_type`：`official`、`state_owned_platform`、`university`、`job_board`、`public_article`。
- `verification_status`：`official`、`verified`、`pending`。
- `source_name`：发布平台或公众号/信息网名称。
- `official_apply_url`：找到时保存企业官方投递页。

公开 JSON 和网页显示一个简洁的状态标识：

- `已核验`：企业官方职位页，或已交叉确认的官方投递链接。
- `待核验`：招聘软件、公众号或就业网的原始公开信息，尚未定位官方投递页。

投递按钮优先打开 `official_apply_url`，其次 `apply_url`，最后 `detail_url`。待核验岗位保留原始信息链接，避免因没有官网链接而遗漏机会。

## 处理流程

```text
公开列表/API/文章页
  -> 提取岗位、公司、地点、届别、要求与来源链接
  -> 2027 届与硬性条件筛选
  -> 尝试从标题、公司名和岗位名查找官方投递页
  -> 写入核验等级与来源类型
  -> 按 公司 + 岗位 + 地点 去重
  -> 官方记录优先覆盖待核验转载记录
  -> 发布有效岗位；待核验岗位有明确标识
```

同一岗位由多个来源发现时，合并为一条：优先官方链接和官方状态，保留其他来源在内部 `alternate_sources` 中。岗位明确截止、官方下线或岗位 ID 连续两次不存在时失效；单次超时、403、429、验证码或异常跳转只标记来源异常，不隐藏历史有效岗位。

## 筛选与安全边界

- 保留明确 2027 届岗位；来源是混合社会岗列表时，必须在岗位标题或官方要求中明确出现 `2027`。
- 继续排除博士专项、硕士及以上硬要求、明确非 2027 届、社招经验硬要求、强制执业资格和无关医学/法律/财务岗。
- 不因“优先”“相关专业”“专业不限”“英语/党员优先”排除。
- 不保存账号、Cookie、Token、联系方式、原始 HTML 或完整文章正文。
- 不绕过登录、验证码、反爬、人机验证、应用内接口或访问控制。

## 验收标准

1. 每个新增来源都有可复现的公开 URL/API 审计记录、fixture 测试和健康状态。
2. 网站可同时展示 `已核验` 与 `待核验` 岗位，并可按状态筛选。
3. 官方投递链接优先；没有官方链接的待核验岗位可打开原始公开来源。
4. 官方记录与转载记录合并后不重复，且官方记录不会被低优先级来源覆盖。
5. 每日 Actions 运行所有已接入来源，某个来源失败不会误删旧岗位。
6. 首轮至少接入 5 个额外的公开来源，其中至少包含一个招聘软件公开页、一个高校就业网或国资平台、一个公开文章/公告类来源。

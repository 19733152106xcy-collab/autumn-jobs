# 2027届秋招岗位库：一期设计

## 目标与边界

建立一个供个人秋招使用的公开岗位索引页。系统每天读取已配置的公开来源，保留成功抓取且符合筛选规则的岗位，完成清洗、匹配、去重、链接检查、安全合并和静态发布。

一期不承诺覆盖全国或全网。微信小程序、登录后页面、验证码页面、未公开职位和无法稳定访问的来源不在自动覆盖承诺内。单个来源失败不得误删历史岗位。

一期不做登录、收藏、简历管理、通知推送、聊天、数据库后台或全量大模型判断。

## 交付顺序

来源可抓取性是首要风险，交付按以下顺序推进：

1. 建立候选来源清单，记录官方地址、页面类型、访问限制和优先级。
2. 技术审核前 10 个候选来源。
3. 从中选择 5 个不同类型的真实来源，打通抓取、筛选、去重、安全合并、公开数据生成和 Pages 发布。
4. 扩展到约 10 个高价值来源，目标构成为：3 个官方招聘系统、2 个设计院或建筑企业官网、2 个央国企招聘平台、2 个高校就业网、1 个补充聚合来源。
5. 连续稳定运行后扩展到 15 个、25 个来源。

第一阶段完成后先展示真实岗位数据、网页效果、来源健康状态和一次完整 Actions 运行结果，再批量扩源。

## 架构

采用 Python 抓取与规则处理、JSON 状态文件、原生 HTML/CSS/JavaScript 静态页面、GitHub Actions 定时执行和 GitHub Pages 发布。

普通 JSON/API、静态 HTML 和已支持的列表详情结构通过 YAML 配置接入；复杂动态网站使用少量专用适配器。只有已支持的来源类型保证“修改配置即可新增来源”，任意未知结构不作此承诺。

Pages 只发布 `site/`。代码仓库即使只发布该目录，公开仓库中的其他提交内容仍可被查看。

## 隐私与数据保留

公开仓库不保存姓名、学校、手机号、简历、Cookie、Token、敏感请求头、完整原始 HTML 或无必要的完整岗位正文。错误日志必须经过脱敏。

`profile.yaml` 只保存匿名规则，例如毕业年份、本科学历、专业组和是否接受跨行业岗位。岗位正文仅在当次运行中用于抽取结构化要求；长期状态保存结构化学历、专业、届别、经验、资格、匹配原因和必要摘要。

公开岗位数据至少包含：

- 公司、岗位、地点、截止日期、发布日期、首次发现日期和更新时间；
- 岗位方向、A/B/C 匹配等级和状态；
- `apply_url` 与 `detail_url`。网页优先打开 `apply_url`，缺失时回退到 `detail_url`。

## 匹配规则

A 类为历史建筑保护、建筑设计、城市更新、文化遗产等直接专业方向；B 类为 BIM、智能建造、建筑数字化、设计管理、工程咨询等建筑相关方向；C 类为 AI、数字化、智慧城市、产品、解决方案、管培生和综合管理等可尝试方向。

只有明确硬条件才直接排除，包括硕士或博士必须、明确仅招其他届别、社会招聘且要求经验、执业资格必须，以及完全无关的纯医学、纯法律和纯财会岗位。“优先”不等于“必须”。

C 类必须至少满足一项最低相关性：专业不限；接受建筑、工程或设计背景；命中 AI、数字化、智慧城市、产品或解决方案方向；管培生或综合管理明确接受本科应届生；岗位描述命中至少一个跨行业关键词。无法判断且不满足最低相关性的岗位不收入公开库，可进入运行期复核摘要。

一期不调用大模型。后续模型只能用于模糊岗位复核或排序，不能直接删除岗位。

## 去重与链接选择

先标准化公司、岗位、地点和追踪参数，再以“标准公司名 + 标准岗位名 + 标准地点”生成基础指纹。结合官方岗位 ID、部门、批次和结构化要求，防止合并同名但不同部门的岗位。

同一岗位优先使用企业官方投递地址，其次为官方详情页、央国企或高校平台，再次为聚合和转载来源。其他来源保存在替代来源列表中。

## 业务数据与运行状态

岗位业务数据与运行状态分离：

- 岗位业务变化：新增、字段变化、失效、投递链接变化。只有这类变化修改岗位状态文件和公开数据，并触发 Pages 重新发布。
- 运行状态变化：检查时间、请求耗时、临时错误、来源健康信息。这些写入运行状态或 Actions 摘要，不得导致公开岗位数据发生无意义变化。

`last_seen` 和 `link_last_checked` 作为运行观测值，不参与岗位业务内容哈希。无业务变化时可以更新 Actions 摘要或短期运行状态，但不制造网站数据提交。

## 失败保护与失效规则

来源抓取失败、岗位数量异常归零或显著下降时，保留该来源历史岗位，不增加其缺失计数，并在 Actions 摘要中报警。

失效规则：

- 截止日期明确已过：`inactive`；
- 官方页面明确显示招聘结束：`inactive`；
- 同一官方岗位 ID 连续两次确认不存在：`inactive`；
- 单次 404 或 410：`suspect`；
- 403、429、验证码、超时或异常跳转首页：`suspect`，不隐藏；
- 连续三次未出现在成功抓取的列表中：仅触发复核，不能单独判定失效。

测试必须覆盖以上状态转换，以及来源失败不误删、突然归零不误删和单次 404 不隐藏。

## 页面

页面名称为“2027届秋招岗位库”。桌面端使用极简表格，手机端使用简洁卡片。只提供今日新增、全部岗位、公司或岗位搜索、岗位方向、城市、匹配等级和更新时间排序。

默认只显示 `active`，但 A/B/C 全部显示。表格只展示公司、岗位、工作地点、截止日期和投递按钮；今日新增标记放在岗位名称旁。

## GitHub Actions 与发布

工作流同时支持每天 7:30（`Asia/Shanghai`）执行和 `workflow_dispatch` 手动执行。定时工作流只在默认分支运行，GitHub 高负载时允许延迟。公开仓库连续 60 天无活动可能被停用定时任务，因此 README 和运行摘要要提示检查方法，并保留手动触发入口。

工作流声明：

```yaml
permissions:
  contents: write
  pages: write
  id-token: write
```

Pages 使用官方 `actions/configure-pages`、`actions/upload-pages-artifact` 和 `actions/deploy-pages`。设置并发锁、超时和部署前校验。只有公开岗位业务数据变化时重新发布 Pages；无岗位变化时在 Actions 摘要中记录运行结果。

## 一期验收

首个可用版本满足：

- 约 10 个高价值来源完成接入并能手动、定时运行；
- 配置来源中成功抓取到的匹配岗位全部保留；
- 单个来源失败不误删历史岗位；
- 搜索、方向、城市、匹配等级和排序可用；
- 同一岗位不重复展示；
- `apply_url` 优先、`detail_url` 可回退；
- 今日新增准确，确认失效岗位隐藏；
- 单次异常只标记 `suspect`；
- 内部状态不保存个人或请求敏感信息；
- 运行状态变化不引发无意义的岗位提交或 Pages 发布；
- 可展示真实岗位数据、页面、来源健康信息和一次完整 Actions 结果。

完成并稳定运行后，再按 15 个、25 个来源逐步扩展。
